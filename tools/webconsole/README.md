# Web 工作台（`tools/webconsole/`）

本目录是**与芯片、厂商工具链无关**的框架包，同时提供本地 Web 工作台的服务端与前端。
它不是"给某块板用的界面"：目标（板子）通过 `targets/` 的适配器与本机台架配置登记进来。

## 启动

两种启动方式，同一个服务：

```powershell
python tools\webconsole\server.py --demo     # 演示数据（无硬件），默认 http://127.0.0.1:8770/
python tools\webconsole\server.py            # 普通模式：按 bench.local.json 装自己的设备
```

| 开关 | 作用 |
| --- | --- |
| `--host` / `--port` | 监听地址与端口（默认 `127.0.0.1:8770`） |
| `--demo` | 证据目录与会话目录指向仓库内的 `demo/`（**合成演示数据**，不是真实台架记录） |
| `--runs-dir <路径>` | 换证据目录；不带 `--demo` 时默认用仓库根的 `runs/` |
| `--open` | 启动后自动打开浏览器 |
| `--stop` / `--force` | 让正在跑的服务优雅退出（`--force` 连握着串口的也停） |
| `--bench <路径>` | 指定本机台架文件（默认按 `PW_BENCH_FILE` > `bench.local.json` 找） |

## 普通模式：接自己的设备

不需要改任何 Python / JavaScript：把 `bench.example.json` 抄一份成 `bench.local.json`，
填上 `devices.<键>.port`（要用的那块板的通信口），重启服务即可。启动后：

1. 点「嗅探」——只读身份查询：**不烧录、不复位、不清设备数据**；
2. 从卡片里选一台设备（卡片上的身份是设备**自报**的）；
3. 点「连接」——身份未知 / 没有匹配固件**都不拦连接**（先连上、会话自己去问身份，
   问不出来就按原始串口收字节）；之后可断开 / 重连。

三条口径：

- **候选口 = 系统串口枚举 ∪ `bench.local.json` 点名的口**（合并去重，台架点名的排前面）：
  平台**不按枚举顺序去猜设备**；一个都没枚举到（例如没装 pyserial）时，“嗅探”给的是一句
  “先去补哪儿”（装 pyserial / 填台架那一格），而不是空白；
- **嗅探不抢占已连接的口**：被本平台自己握着的口不会重开、也不会多发一个字节
  （卡片上会写明“平台已连接该通信口：本轮未重复打开”）；
- 普通模式是**只读**的：不构建、不烧录、不动调制线（打开口不写 DTR/RTS ⇒ 不复位设备）。

### 没有硬件也能把真实串口栈跑一遍

`devices.<键>.port` 可以写成 **pyserial 的 URL**：

| 写法 | 得到什么 |
| --- | --- |
| `loop://` | 写出去的字节原样回显（验通道、验收发计数） |
| `socket://127.0.0.1:9000` | 连一台自己的**虚拟板**（一个几十行的 TCP 小服务） |

它不是替身插件：打开 / 写 / 读 / 超时 / 关全部走 pyserial 的真路径。

## 三种模式

页面顶部就是模式菜单（自动验证 / 实时观察 / 离线诊断）。**切模式本身不产生任何动作**：
不构建、不烧录、不复位，也不动串口调制线。

| 模式 | 演示模式下能看到什么 |
| --- | --- |
| 自动验证 | 随仓库发运的那份合成 run（`demo/runs/`）：6 个阶段卡、断言 6/6、六窗证据齐全。演示目标是**只读**的（core 层假目标没有构建/烧录链，能力表里如实写着 `unsupported`），所以「启动验证」不会真跑 —— 要看回放，请在「历史运行」里打开那份 run |
| 实时观察 | 设备卡是演示替身（端口 `FAKE0`，不接真实硬件）。要连它请先点「嗅探」再「连接」；替身不会主动说话，收到 0 字节是正常的 —— 想看清"一次观察会话长什么样"，请用「离线诊断」打开 `demo/observe-sessions/` 里那份合成会话 |
| 离线诊断 | 回看历史 run 与会话、检索整份证据、导入导出诊断包（不打开串口） |
