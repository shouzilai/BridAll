# 用 AI 上手这个平台

这份文档是给**刚拿到这个仓库的人**的：怎么开始用，以及**怎么让 AI（Copilot / Cursor / Claude Code 等）
帮你用**。所有提示词都可以直接复制。

> 一句话：这个仓库自带一份**给 Agent 的短入口** —— [`AGENT_WORKFLOW.md`](../AGENT_WORKFLOW.md)。
> 你不需要把整个仓库喂给 AI，**让 AI 先读那一份**就行。

## 1. 先建立一个心智模型

```text
工具链事实（在你自己的电脑上，不进仓库）
        │  由 bench.local.json 提供：工具在哪、板子插在哪个口
        ▼
   适配器（Adapter）——"这块板怎么构建/烧录/观察、怎样算成功"
        │  参考实现住在 targets/；你自己的板子用 create-adapter 生成
        ▼
   平台（本仓库）——受约束地执行、判成功/失败、留证据、该停就停
```

三句话：

1. **平台不含你的硬件工程和厂商工具**，它规定"应该声明什么、怎么执行、怎样算成功、失败何时停、怎么证明做完"；
2. **不配任何东西也能用**：普通模式下候选口 = 系统串口枚举 + `bench.local.json` 点名的口，未适配的口能连、能收发；
3. **写设备的动作（烧录 / 复位）永远要两条显式同意**，没有同意就一个字节都不写。

## 2. 你属于哪一类使用者

| 你想做的事 | 先读 | 第一条命令 | 要 AI 做什么 |
| --- | --- | --- | --- |
| 只想把它当**串口终端**看设备输出 | 本文 §3.1 | `python tools\webconsole\server.py` | 带你走完"嗅探 → 选口 → 连接 → 收发"，不改代码 |
| 想先确认**这台电脑能不能跑** | `INSTALL.md` | `python tools\doctor.py` | 逐条解释 `WARN` / `FAIL` 与要补什么 |
| 想把自己**不认识的板子**接进来 | `AGENT_WORKFLOW.md` | `python tools\hwops.py create-adapter …` | 生成骨架、按生成物 README 的清单推进 |
| 想接**完整的构建 / 烧录链** | `docs/adapter-guide.md` | 同上，再加 `--fake` 跑通 | 写适配器声明，先假后真 |
| 想给这个仓库**提改动** | `HANDOFF.md` | `python tests\run_all.py` | 按"完成定义"收尾并贴证据（§3.6） |

## 3. 提示词模板（可直接复制）

通用前提：**让 AI 只读仓库里的文件，不要凭印象编**；并且**每一步都要它给出原始输出**。

### 3.1 "我只想当串口终端用"（零配置）

```text
读 README.md 的「在浏览器里用」一节和 INSTALL.md 的「三步」。
我现在只想把这台电脑上的串口当普通终端看输出，不想接任何适配器。

请：
1. 先跑 python tools\doctor.py，把输出原文给我，并只解释对我有影响的 WARN/FAIL；
2. 然后告诉我怎么用 python tools\webconsole\server.py 启动、浏览器打开哪个地址、
   在页面上依次点哪里（嗅探 → 选口 → 连接 → 在终端窗口收发）；
3. 明确告诉我：哪些操作会碰设备（会写字节/会复位），哪些只是只读。

不要改任何代码，不要新增文件。
```

### 3.2 "先看看这块板到底在说什么"

```text
我用串口接了块不认识的板子。请只做**只读观察**：
1. 启动 Web 工作台并做一次嗅探，把这一轮结论给我，并逐项说明：
   候选口是从"系统串口枚举"来的还是从 bench.local.json 来的？卡片上身份是"已确认""没问到"还是"不可用"？
2. 如果身份没问到，告诉我为什么（原始输出里写的理由），不要猜芯片型号；
3. 另外告诉我：嗅探对每个口最多问几次、会不会重开已经连上的口。

不要向任何口发送身份查询以外的字节，不要烧录、不要复位。
```

### 3.3 "把我的板子按适配器接进来"（推荐路径）

```text
读 AGENT_WORKFLOW.md 和 docs/adapter-guide.md，然后：

1. 跑 python tools\hwops.py create-adapter --out my_target --id my-board --label "我的板子"；
2. 把生成的四样东西各是干什么的讲给我；
3. 打开 my_target\README.md 那份"还差哪几件事才算接完"的清单，逐条问我值；
   我答不出来的就先标"待定"，不要替我编工具路径或端口名；
4. 每一步都用假工具先跑：--fake，跑通再谈真机。

如果某个必需的值我没提供，停下来问我，不要猜。
```

### 3.4 "跑一次真的"（要授权的动作）

```text
我准备在真机上跑 preflight,build,flash,verify。

在你拿到我的明确同意之前，不要执行 flash。请先：
1. 告诉我这一步需要的两条显式同意分别是什么、我该用什么理由；
2. 告诉我如果失败会怎样（会不会重试、什么时候熔断、怎么恢复）；
3. 把你要执行的完整命令原文打印给我，等我回"同意"再执行。
```

### 3.5 "出问题了，别猜"

```text
当前结论不是"通过"。请：
1. 把原始输出、退出码、故障码贴全（不要只给一句总结）；
2. 退出码按 AGENT_WORKFLOW.md §3 解释（0 通过 / 1 有失败 / 2 被拒 / 3 没跑完）；
3. 如果是"台架键未配置"或"工具不可用"，把需要我填的键名与示例形状列出来，
   不要猜路径、不要写死盘符；
4. 告诉我下一步最小动作是什么。
```

### 3.6 "按完成定义收尾"（改仓库时）

```text
按 AGENT_WORKFLOW.md §6 的完成定义收尾：
1. python tests\test_hwops_contract.py
2. python tools\hwops.py check
3. python tools\hwops.py opensource-audit
4. 如果有 Web 相关改动再跑 python tests\run_all.py

把每条命令的原始输出与退出码贴给我；有失败就报告失败，不要为了让结果变绿而改判据。
提交信息里写清：改了什么、用什么命令验的、结果是什么。
```

### 3.7 "我要提交自己的东西"（先自检有没有夹带本机信息）

```text
我准备提交。请先跑 python tools\hwops.py opensource-audit --scope all，
把命中的文件、行号与命中理由逐条列给我，并告诉我每一处是"必须删掉"还是"改成中性写法"。

特别检查：有没有绝对路径、串口名、序列号、私有工程名、真实证据（runs/ sniff/ observe-sessions/）被带进版本库。
```

## 4. 不要让 AI 做的事

| 别做 | 为什么 | 会被什么挡住 |
| --- | --- | --- |
| 在 core 里按"某块板"写分支 | 框架要跟芯片无关 | `hwops.py check` 的 Core 泄漏检查 |
| 绕开登记表直接拼厂商命令行 | 判据与失败码就失效了 | `check` 的旁路检查 |
| 为了让测试变绿而放松判据 | 那等于把"没验证"说成"验证了" | 契约测试与机器检查 |
| 把绝对路径 / 串口名 / 真实证据提交进仓库 | 那是**你这台机器的事实**，换台机器就不成立 | `opensource-audit` 会逐行报出来 |
| 没有你的明确同意就烧录 / 复位 | 会覆盖设备里的东西 | 两条显式同意 + 熔断 |
| 熔断后重试 | 同一个故障连着两次之后第三次会被拒 | `fuse_open`，要人工处置后 `fuse --clear` |

## 5. 想让 AI 更靠谱，加这三句

在提示词末尾加上它们，效果通常比写更多细节更好：

1. **"先读 `AGENT_WORKFLOW.md`，再动手。"** —— 那是本仓库给 Agent 的短入口（命令 + 判据 + 停止条件）；
2. **"只跑不需要硬件的部分（`--fake` / `--demo`），真机的事先问我。"** —— 把不可逆的动作挡在你手里；
3. **"把原始输出贴给我，不要只给结论。"** —— 这个平台的每一条结论都应当是**可复核的**，
   包括 AI 说"我验过了"的时候。
